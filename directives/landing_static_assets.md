# Static assets and images on App Hosting

Landing visuals live in `src/assets/landing/`, branding logos/emblems live in `src/assets/branding/`, storefront photos live in `src/assets/about/`, and team photos live in `src/assets/team/`. These are statically imported by their components. Next.js emits these files under `/_next/static/media/` during `npm run build`.

Full-bleed hero photography must be large enough for desktop cover rendering (at least roughly 1600px wide and 900px tall). A 1024px-wide source becomes visibly soft on 1440p and wider viewports. Theme-specific readability overlays should concentrate opacity behind the copy and fade to transparent before the product focal point; do not apply a uniform translucent wrapper over the entire photograph because it makes light mode look hazy.

The Firebase App Hosting deployment returns the application's 404 page for root-level `public/` image URLs such as `/feature-1.webp` or `/netcodex-emblem.png`, even though those files load in `next dev` and are tracked in Git. Additionally, Firebase App Hosting does not provide built-in server-side image optimization (`/_next/image`), so `images: { unoptimized: true }` is enabled in `next.config.ts`. For all static app imagery, use static imports and `next/image` rather than root-relative `public/` string paths. After a change, run `npm run typecheck`, lint the touched components, and `npm run build`; confirm the expected files appear in `.next/static/media/`. After rollout, verify each image renders with a nonzero natural width in the browser.

The featured Prism 5 and King 45 clips live in `public/videos/` and are served through `/landing-video/[name]`, with the files included in Next output tracing. This avoids relying on root-level public asset URLs in App Hosting. Each clip has a statically imported WebP poster; the first poster is preloaded in server HTML. Check the route with a byte-range request (206), then confirm both videos play after deployment.

The landing hero owns five slides: Prism 5, King 45, Bottleneck Analysis, Buildbot Build Critique, and Instant AI Build Generation. Keep their compact indicators centered at the bottom with 44px interaction targets around the visible dots. Slide changes fade the media and copy together using one synchronized 200ms crossfade; use `AnimatePresence` sync mode so copy entry does not wait for the previous copy to exit. Reduced-motion users receive an instant change. Keep the Prism 5 and King 45 video elements mounted so both media files can preload; pause the inactive video and play the active one. The video replaces its poster as soon as its `playing` event fires, without an additional opacity transition. This prevents the poster from flashing again when a user returns to a product slide. Do not restore a separate landing features section or Features navigation item.

The Featured Products section sits between the hero and Featured Systems. It requests `/api/featured-parts` only near the viewport; the endpoint reuses `listPublicPartsCatalog`, sorts valid prices descending, and sends the first twelve small card records. Display four columns on desktop, two on small screens, and one on narrow phones. Product cards link to `/parts/[productId]`, and View All links to `/parts`. Keep the landing route's server HTML free of catalog reads so hero preload remains early.

The two shopping panels immediately after Featured Systems use statically imported transparent cutouts in `src/assets/landing/prebuilt-pcs.png` and `custom-builder-parts.png`. Their CTAs use the same filled cyan treatment as the hero action and link to the public `/pre-builts` and `/builder` routes.

The final landing CTA has been replaced by `WhyChooseSection`. It uses the statically imported Netcodex logo at low opacity behind the heading and shows four responsive cards: Nationwide Shipping, Authorized Dealer, Secure Transactions, and Top-notch Support. Keep card copy aligned with the application's actual checkout, delivery, and support flows; the FAQ contains broader commercial claims that are not all backed by live integrations. For local browser verification, sandboxed Playwright may not see the installed Chromium executable; rerun the test with the available host browser instead of installing a second browser into the sandbox.

`npm run lint` was verified to run cleanly on 2026-10-16. Next.js 15 prints a deprecation notice for `next lint`; this is separate from ESLint warnings. Run the normal repository command before using a fallback.

## Production performance verification

Stop this repository's development server before building and serving production on port 9002. Do not run typecheck while Next.js is deleting/regenerating `.next/types`, or browser benchmarks while other browser tests run. Use `npm run build`, `npm run start -- -p 9002`, then `node execution/audit_landing_performance.mjs http://127.0.0.1:9002 tmp/performance/local.json 3`. Compare repeated hard navigations under matching conditions; keep hosted measurements separate from local results and soft-navigation screenshots. `AUDIT_TRACE=1` optionally saves a Chrome trace for the first mobile cold run; use a separate run for tracing to avoid changing benchmark conditions.

The landing route is gated on restored Auth. `src/app/page.tsx` must emit the hero's responsive image preload in server HTML using the same `getImageProps` options as `HeroSection`. This starts the public asset download before hydration without exposing protected content or bypassing role verification. Only the initial above-the-fold image gets high priority. Keep feature images lazy and reserve dimensions. The lower-page prebuilt carousel loads near the viewport; its anchor must exist before the carousel mounts, and the first cards must not compete with the hero on initial navigation.

Keep one settings subscription in `SiteSettingsProvider`, shared with `AppLayout`. Firestore may coalesce duplicate network listeners, so do not claim a measured read-cost reduction from removing a duplicate React subscriber. AI advisor jobs load on first advisor visit and retain their scope during later client navigation; verify that pending jobs survive leaving and returning to the page. Check `tests/landing-performance.spec.ts` and `tests/auth-role-navigation.spec.ts` against production after changing these boundaries.
