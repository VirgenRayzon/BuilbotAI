# BuildbotAI user input, system process, and output audit

## Introduction

This document follows a simple order: **user input → system process → output**. A **user input** is something a person types, chooses, scans, or clicks. A **system process** is the work BuildbotAI does next, such as checking a form, reading parts, or saving a reservation. The **visible output** is what the person sees, such as a list, message, result, or file. The **system output** is a saved change or a request sent to another service. For example, when a customer confirms a reservation, the app checks stock, shows the result, and may save an order and lower the stock.

The audit is based on the repository code reviewed on 29 October 2026. It covers the 24 page routes found in the project and the main actions people can take on those pages. It does not prove that Firebase, Google AI, email, or a deployed site is working at this moment. A feature marked **Preview** is experimental and is listed separately below. A feature that exists in source code but has no found page entry is not treated as an available page feature.

## How to read the tables

| Column | Meaning |
| --- | --- |
| Area | The page or tool where the action starts. |
| User input | What a person enters, chooses, scans, or clicks. |
| System process | What the app checks, reads, or works out before giving a result. |
| Visible output | What the app shows or gives back to that person. |
| System output | What the app saves, changes, sends, or returns to another part of the system. **No saved change** means the action only changes the current view or reads data. |
| Source | The main code files checked for the row. Paths are relative to the project root. |

The tables show successful paths in plain words. Invalid input, missing permission, missing stock, and service errors can instead show an error. A button opening another page is a visible output, but it does not by itself save a new record.

## Important limits found during the audit

- A **real reservation** changes Firestore stock and creates a saved order. The **Preview checkout** uses browser data and is only a sample.
- The Profile cancellation dialog offers a route to Contact Staff. Its visible choice is not the same as a completed order cancellation.
- A guest can submit the Contact form, but the in-app conversation view is tied to a signed-in customer account.
- `SmartBudget` has AI code in `src/components/smart-budget.tsx`, but no page entry was found in the reviewed source. It is not listed as a current user page feature.
- This audit checks code paths, not live Firebase records, deployed access rules, external email delivery, or actual AI responses.
