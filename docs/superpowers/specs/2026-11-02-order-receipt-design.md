# Customer Order Receipt Design

## Intent

Add a customer-facing receipt download beside Total Amount. The receipt provides a legitimate, itemized proof of purchase patterned after the supplied PC-store warranty receipt while using Netcodex branding and the order's authoritative data.

## Requirements

- Generate a single-page US Letter PDF entirely in the browser with the existing `pdf-lib` dependency.
- Include Netcodex identity and showroom address, receipt/order metadata, customer and delivery details, SKU/item/price/quantity/total columns, subtotal/fees/discount/total, payment method/reference, and concise warranty/DOA terms.
- Never invent tax registration data, employee identities, payment amounts tendered, or warranty periods not present in the application policy.
- Place a compact Download Receipt button immediately after Total Amount in the customer order header.
- Keep all content on one page by adapting row height and typography to the item count and truncating only overly long descriptions.

## Approaches

- Chosen: browser-side `pdf-lib` generation. It needs no new dependency or API and gives deterministic Letter sizing and page count.
- Rejected: server endpoint. It adds authentication and deployment complexity without improving this customer-owned download.
- Rejected: browser print HTML. Print margins and scaling cannot guarantee one page.

## Verification

Automated tests reopen the generated bytes and assert one page, exact Letter dimensions, expected receipt text, totals, and line items. Typecheck, lint, the order regression suite, and a rendered-PDF visual inspection complete verification.
